Context Window Economics

"The context window is a public good."

❌ Wrong approach: Write detailed explanations assuming Claude knows nothing.

✅ Right way: Challenge each token: "Does Claude really need this?"

Key Insight
Token Cost = f(relevance × necessity)

Your Skill competes with: system prompt, conversation history, other Skills, and the actual request. Every unnecessary token degrades Claude's performance.

Module 2 / 5

Degrees of Freedom

"Match specificity to task fragility."

❌ Wrong approach: Use same level of detail for all instructions.

✅ Right way: Tight guardrails for fragile ops, loose guidance for creative tasks.

The Bridge Analogy
Narrow bridge + cliffs: One safe path. Exact instructions. (DB migrations)
Open field: Many paths work. General direction. (Code reviews)
Freedom Calibrator PRACTICE

Classify each task by appropriate freedom level.

Database migration script
Code review feedback
Report generation with template
API key rotation

FRAGILE OPERATIONS NEED TIGHT RAILS. CREATIVE TASKS NEED SPACE.

Module 3 / 5

Progressive Disclosure

"SKILL.md is a table of contents, not the book."

❌ Wrong approach: Dump everything into SKILL.md.

✅ Right way: Overview in SKILL.md, details in referenced files loaded on-demand.

How Claude Loads Skills
1. Startup: Only name + description loaded
2. Triggered: SKILL.md body loaded
3. As needed: Reference files loaded
File Structure Simulator CHALLENGE

Design a BigQuery Skill structure. See how different architectures affect token usage.

⚠️ Anti-Pattern

Deeply nested references (3+ levels) cause partial reads. Keep references one level deep from SKILL.md.

BUNDLE COMPREHENSIVE RESOURCES. NO CONTEXT PENALTY UNTIL ACCESSED.

Module 4 / 5

Feedback Loops

"Run validator → fix errors → repeat."

❌ Wrong approach: Execute complex operations in one shot.

✅ Right way: Plan → Validate → Execute → Verify

Why Loops Matter
P(success) = P(plan_correct) × P(execute_correct)

Without validation: 0.8 × 0.8 = 0.64

With validation loop: 0.95 × 0.95 = 0.90

VALIDATION CATCHES ERRORS EARLY. SCRIPTS SOLVE, DON'T PUNT.

Module 5 / 5

Discovery & Description

"The description enables Skill selection from 100+ options."

❌ Wrong approach: "Helps with documents"

✅ Right way: "Extract text and tables from PDF files. Use when working with PDFs or document extraction."

Description Formula
[What it does] + [Trigger keywords] + [When to use]

Always third person. Max 1024 chars. No XML tags.

Description Scorer FINAL

Write a description for an Excel analysis Skill. Get scored on discoverability.

Naming Convention

Use gerund form: processing-pdfs, analyzing-spreadsheets

Lowercase, numbers, hyphens only. Max 64 chars.

SPECIFIC DESCRIPTIONS WIN. VAGUE DESCRIPTIONS LOSE.
