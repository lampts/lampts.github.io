That's right!

Standard attention computes an L × L matrix. This is computed every single time we generate a token!

Not quite.

Standard attention computes scores for every pair of tokens — that's L × L scores!

Inside Attention: Q, K, V

Attention uses three matrices derived from your input:

Q
Query
"What am I looking for?"
K
Key
"What do I contain?"
V
Value
"What info do I carry?"
# For each token, compute Q, K, V
Q = embeddings @ W_Q
K = embeddings @ W_K
V = embeddings @ W_V
# Attention scores
scores = Q @ K.T
output = softmax(scores) @ V

When we add a NEW token to the sequence, which matrices change?

Exactly!

The old rows don't change! K and V for "Mary" stay the same. This is the key insight.

Think about it:

K = embeddings @ W_K. If old embeddings don't change, their K values don't either!

The KV Cache

Since K and V for old tokens never change, we can cache them!

With KV caching, we only compute K and V for the new token, then append to the cache.

🎉 Summary

What exactly gets cached?

The K and V matrices from the attention mechanism.

K = embeddings @ W_K # Cached!
V = embeddings @ W_V # Cached!

Why does it work?

K and V for a token only depend on that token's position, not future tokens.

Where do the savings come from?

  1. Within generation: Don't recompute K, V for past tokens
  2. Across requests: Share cache for same prompt prefix
