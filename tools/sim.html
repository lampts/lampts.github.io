Revenue Forecasting via Monte Carlo Simulation

Autoregressive time series modeling with probabilistic simulation for realistic scenario planning

Interactive Tool · Updated November 2025

Traditional forecasting methods rely on point estimates that obscure uncertainty. This tool runs thousands of simulations to generate a probability distribution of possible outcomes, revealing both expected values and tail risks through autoregressive time series modeling.

Unlike naive approaches that treat each day independently, the default autoregressive model captures temporal dependencies: yesterday's strong performance predicts today's strength, weekly patterns repeat, and recent trends persist. Features include lag₁ (daily momentum), lag₇ (weekly seasonality), and rolling averages (MA7, MA14) that adapt to changing conditions.

The model learns optimal feature weights from historical data via linear regression, explaining which factors matter most. For comparison, a simpler baseline model using fixed volatility weights (60% current + 40% previous) is also available, though it ignores autocorrelation and produces less realistic forecasts.

Methodology

Autoregressive Model (Default)

The autoregressive (AR) model treats revenue as a time series where each observation depends on recent history. This captures three critical patterns naive models miss:

  • Momentum: Strong days tend to follow strong days (positive autocorrelation)
  • Seasonality: Weekly patterns repeat (Monday ≠ Friday)
  • Trend adaptation: Moving averages track regime shifts

Feature Engineering

For each day t, we extract five features from history: 

lag₁  = revenue_{t-1}           # Yesterday's value (momentum)
lag₇  = revenue_{t-7}           # Same weekday last week (seasonality)
MA7   = mean(revenue_{t-7:t})   # Recent 7-day trend
MA14  = mean(revenue_{t-14:t})  # Medium 14-day trend
bias  = 1.0                     # Constant term

Model Fitting

We concatenate previous period + current period into a single time series of length n, then fit via ordinary least squares (OLS): 

# Build design matrix X and target vector y
for t in [1, 2, ..., n]:
    X[t] = [lag₁, lag₇, MA7, MA14, 1.0]
    y[t] = actual_revenue[t]

# Solve normal equations: (X'X)w = X'y
weights = (X'X)⁻¹ X'y
residual_σ = std(y - Xw)

This yields five learned weights w = [w₁, w₇, w₇ₐ, w₁₄ₐ, w₀] indicating feature importance. Model quality metrics:

  • R²: Fraction of variance explained (R² = 1 - SS_res/SS_tot). Values >0.2 indicate meaningful patterns.
  • σ: Residual standard deviation. Smaller σ means tighter predictions.

Autoregressive Simulation

Unlike i.i.d. sampling, each simulated day depends on previous simulated days: 

sim_history = actual_history.copy()

for day in remaining_days:
    # Extract features from simulated history
    features = [lag₁, lag₇, MA7, MA14, 1.0]
    
    # Linear prediction + gaussian noise
    prediction = dot(features, weights)
    revenue = prediction + N(0, σ)
    
    # Apply independent shocks
    if day in event_days:
        revenue *= U(1.05, 1.15)
    if random() < P(downtime):
        revenue *= (1 - U(0.05, 0.10))
    
    # Append to history for next iteration
    sim_history.append(revenue)

This stateful approach produces realistic trajectories where strong periods persist and weekly patterns emerge naturally, unlike the erratic jumps of i.i.d. sampling.

Simple Model (Baseline Comparison)

The simple model treats each day as independent (i.i.d.) with fixed parameters: 

# Fixed volatility weighting
σ_forecast = 0.60 × σ_current + 0.40 × σ_previous_2nd_half

# Fixed downtrend
baseline_t = μ - β × t × 0.5

# Independent sampling (no history dependence)
revenue_t = N(baseline_t, σ_forecast)

This ignores autocorrelation and produces higher estimated variance (overestimating risk). While simpler to explain, it's less accurate for revenue streams with momentum or patterns.

Independent Shocks (Both Models)

After computing the baseline prediction, both models apply multiplicative shocks for events (seasonal promotions) and downtime (system outages): 

if day ∈ event_days:
    revenue × U(1 + boost_min%, 1 + boost_max%)
if random() < P(downtime):
    revenue × (1 - U(impact_min%, impact_max%))

These shocks are modeled as independent because they're driven by external factors (marketing calendar, infrastructure reliability) rather than revenue dynamics.

Statistical Rigor

Wilson Score Confidence Intervals

For success rate P(total ≥ target), we use Wilson score intervals rather than normal approximation. Given k successes in n simulations: 

p̂ = k/n
center = (p̂ + z²/2n) / (1 + z²/n)
margin = z√(p̂(1-p̂)/n + z²/4n²) / (1 + z²/n)
CI = [center - margin, center + margin]

where z = 1.96 for 95% confidence. This method provides accurate coverage even when p̂ is near 0 or 1, unlike normal approximation which fails at extremes.

Risk Measures

Percentiles map to planning scenarios:

  • P10: Pessimistic case (10% chance of doing worse)
  • P50: Median outcome (most likely scenario)
  • P90: Optimistic case (10% chance of doing better)

The gap P90 - P10 indicates forecast uncertainty. Narrow gaps suggest high confidence; wide gaps indicate volatile outcomes.

Model Selection Guidance

Use Autoregressive When:

  • You have 20+ days of history (sufficient data for 5-parameter model)
  • Revenue shows day-to-day persistence or weekly patterns
  • R² > 0.2 after fitting (indicating learnable structure)
  • You need realistic scenario trajectories for planning

Use Simple Model When:

  • History is limited (<14 days available)
  • Revenue is truly random (R² < 0.1, no patterns)
  • You need fastest computation (5x faster)
  • Explaining to non-technical audience (simpler conceptually)

Recommended: Start with autoregressive (default). If R² is low (<0.15) or results seem unrealistic, compare against simple model. The two approaches bound the uncertainty: autoregressive captures dependencies (realistic), simple assumes independence (conservative).
